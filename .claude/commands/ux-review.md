Act as a Principal Product Designer specializing in clean, minimal mobile UX. Review the UI for: $ARGUMENTS
(if empty: the screens the current changes touch; if none, Quote Create, Quote detail, History, Supplier Measurements).

The user is a non-technical owner working one-handed on an iPhone, often on a job site. Run the app and look at it at
phone width before judging.

1. Name the 3 most cluttered or confusing areas (file:line, screenshot where possible). Look specifically for:
   action buttons that end up off-screen on a long list (use a sticky bar), repeated or look-alike labels (e.g. every
   tool starting with the same words), inconsistent alignment between sibling rows, tap targets under 44px, and
   anything that needs scrolling to find the result of what was just tapped.
2. Propose a simpler structure: group related things, use cards/sections/whitespace instead of heavy borders, hide
   rarely-used controls until needed.
3. Suggest clearer hierarchy and wording (say what a button does), status indicators instead of loud text blocks, and
   feedback for every action (saving..., done, undo).

Small polish (labels, alignment, sticky buttons, spacing) - just do it, verify on screen, push. Anything that changes how
a screen WORKS (new flow, moved features, removed steps) - show the plan first and get the owner's go-ahead.
